# 部署环境

这份文档说清楚两件事：**这套东西需要什么样的机器**，以及**它在什么环境里真正跑过**。
凡是没有实测过的，这里会直接标「未验证」，不猜。

> 仓库里没有任何真实主机信息：示例地址一律 `127.0.0.1` / RFC5737 段（`203.0.113.0/24`），
> 示例容器名一律 `example-*` 或上游软件的默认名。

---

## 1. 一句话结论

一台 **Linux 小机器 + Docker + Python 3.8+** 就够。没有数据库、没有 Node、没有 pip 依赖、不需要外网。

---

## 2. 实测过的两种环境

### A. 生产（容器路线，长期在线跑）

| 项 | 实测值 |
|---|---|
| 系统 | Ubuntu 22.04 LTS，x86_64 |
| 规格 | 2 vCPU / 2 GB 内存 / 40 GB 系统盘（**小到这种程度能跑**） |
| Python | 系统自带 `python3`（3.10），跑采集器与登录网关 |
| Docker | Docker Engine + Compose v2（`docker compose` 子命令，不是老的 `docker-compose`） |
| Caddy | `caddy:2-alpine`（2.7 系）跑大屏站点；同一台机上另有一个 **2.4.6** 的实例，同一份配置语法两边都验过 |
| 加固 | systemd 管网关与采集器定时器；fail2ban 读 Caddy 访问日志封 IP |
| 结果 | 三个业务容器 + 大屏 + 网关在这个规格上共存，负载压力主要来自业务侧，大屏本身可忽略 |

### B. 开发机（Windows，看效果 + 改代码）

| 项 | 实测值 |
|---|---|
| 系统 | Windows 10/11，PowerShell 5.1 |
| Python | 3.14（用 `py` 启动器；`python`/`python3` 可能是应用商店占位 stub，会无输出直接退出） |
| Docker | **没有**（所以本机只跑 `tools/demo.py`、采集器、网关；`caddy validate` 得上服务器做） |
| 结果 | 采集器能跑，但 `/proc` 不存在 → 内存卡降级为 `{"error": "/proc/meminfo 不存在"}`，属预期 |

## 3. 硬性要求

| 依赖 | 最低 | 用途 | 缺了会怎样 |
|---|---|---|---|
| Linux | 任意现代发行版（需要 `/proc`） | 采集器读内存/负载 | Windows/macOS 上内存卡降级，其它照常 |
| Python | **3.8+**（语法已按 3.8 校验） | 采集器、网关、两个工具脚本 | 起不来 |
| `docker` 命令行 | 20.10+ | 采集容器状态、`docker exec` 判活 | 容器卡片全部 `missing` |
| `openssl` | 1.1.1+ | `deploy/gen_certs.sh` 生成自签证书 | 用不了 HTTPS，或自己外购证书 |
| Caddy | **2.4+**（2.4.6 与 2.7 实测） | 反代 + 静态站 + Cookie 匹配 | 站点起不来 |
| systemd | 任意 | 可选：管网关进程与采集定时器 | 可以换 cron + `nohup`，但要自己保活 |

可选：`fail2ban`（撞口令防护，缺了不影响页面）、`iptables`（fail2ban 的 action 用它封 `DOCKER-USER` 链）。

---

## 4. 不需要的东西

- ❌ 数据库（状态全在 JSON 文件里）
- ❌ Node / npm / 打包工具（前端是一个 HTML + 一个 JS，没有构建步骤）
- ❌ `pip install`（**零第三方依赖**：采集器、网关、两个工具脚本全用标准库）
- ❌ 外网访问（除了你浏览器访问它；页面不加载任何 CDN 资源）
- ❌ HTTPS 证书采购（自签够用，`/ca.crt` 就是给手机装信任用的）

## 5. 端口与目录

| 端口 | 谁在听 | 是否对外 |
|---|---|---|
| `8443`（可改 `DASH_PUBLISH_PORT`） | Caddy | ✅ 唯一需要放行的口 |
| `8766`（`DASH_AUTH_PORT`） | 登录网关 | ❌ 只允许本机/容器内网访问，**不要 publish** |
| `8445`（可选第二站点） | Caddy | ⭕ 按需 |

| 目录 | 要求 |
|---|---|
| `<部署根>/site` | 只读，Caddy 的站点根 |
| `<部署根>/status` | **可写**：采集器写 `health.json`，业务侧写状态文件；不要放日志 |
| `<部署根>/logs` | 可写：Caddy 访问日志（fail2ban 读它） |
| `<部署根>/certs` | `ca.key` / `server.key` 必须 `600` |
| `<部署根>/auth/auth.json` | **必须 `600`**，里面有会话令牌 |

权限：网关与采集器建议用同一个低权限用户（`install.sh` 会建 `dash`）跑；`docker` 命令需要该用户在 `docker` 组里。

## 6. 资源占用（实测口径）

| 组件 | 占用 |
|---|---|
| 前端 | 静态文件：`dash.html` 27 KB + `config.js` 2 KB + 立绘 ~64 KB，浏览器加载完就不再请求（`health.json` 每 `refreshMs` 取一次） |
| 采集器 | **一次性进程**，2 分钟跑一次；扫 `data_dir` 时受 `scan_file_cap`（默认 40 万文件）约束 |
| 登录网关 | 常驻，纯标准库 `http.server`，量级与一个空闲 `python3` 进程相当 |
| 磁盘 | 仓库本身 ~260 KB；运行期增量只有 `health.json`（几 KB）+ 访问日志 |

> 1 核 1 G 也能跑，2 G 更稳（同一台机上可能还跑着别的服务）。

---

## 7. 浏览器基线

前端只用了 CSS 变量、`inset`、`flex/grid`、`fetch`、`prefers-reduced-motion` 这些早就稳定的特性；
**没有** `backdrop-filter`、`:has()`、`color-mix()`、`aspect-ratio` 这类新东西。
所以：

- Chromium 87+ / Edge 87+：实测通过
- Firefox 66+、Safari 14.1+：按特性推断可用，**未逐项实测**
- 手机端 390×844 与桌面 1400 宽实测通过；系统开了「减弱动效」时会停掉气泡与游动动画（设计如此）

## 8. 已知不支持 / 未验证

| 情况 | 说明 |
|---|---|
| Windows / macOS 当**服务器** | 能跑（`tools/demo.py` 就是），但容器卡片、`/proc` 内存、`docker` 相关都会降级；正式部署不要这么干 |
| 非 Linux 的 `/proc` 替代 | 未实现；需要的话在 `collect_mem()` 里加分支 |
| 无 Docker 的机器 | 容器卡片会全 `missing`；其它卡片照常 |
| Caddy < 2.4 | 未验证（`handle`/`header` 语法在这些老版本上有差异） |
| Python 3.7 及更早 | 不支持（语法基线 3.8） |
| 反向代理套反向代理 | 未验证；网关靠 `X-Forwarded-For` 之外的原始信息不敏感，但 Cookies 的 `Secure` 需要最外层是 HTTPS |
| 多实例共用一个 `status/` | 不支持（`health.json` 会被互相覆盖） |

## 9. 上手前的一页核对

```bash
uname -a                       # Linux x86_64
python3 -V                     # >= 3.8
docker --version               # >= 20.10
docker compose version         # v2
which openssl && openssl version
caddy version                  # >= 2.4（容器路线可省）
systemctl --version            # 有就用来管服务
ss -lntp | grep -E '8443|8766' # 端口别被占
df -h /opt                     # 留几百 MB
```

全绿就可以照 [README 第 4 节](../README.md#4-快速开始-a宿主直装推荐) 装。

## 10. 迁移到另一台机器要带走什么

| 带走 | 说明 |
|---|---|
| `auth/auth.json` | 带过去就不必重新生成口令（但**别提交到仓库**） |
| `certs/` | 换了证书手机要重装 `ca.crt`；或者直接重新生成一套 |
| `status/` 下的状态文件 | 可选，纯展示数据 |
| `health.config.json` | 每人环境不同，属于**部署方自己的配置**，不进仓库 |

不用带：`site/`、`collector/`、`auth/*.py`、`deploy/`（都在仓库里）。
